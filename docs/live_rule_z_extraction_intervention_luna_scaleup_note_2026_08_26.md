# Live Rule-Z Extraction / Intervention Luna Scale-Up - 2026-08-26

## Question

The seed-67 pilot separated literal extraction from downstream intervention
computation and found three local effects:

- direct source computation outperformed the two literal-ledger paths overall;
- target preannouncement improved active-conclusion extraction while degrading
  active-rule extraction; and
- four model-literal rows failed after all eight upstream typed values were
  exact, although all four belonged to one omitted-dependency case.

This prospectively registered scale-up asks whether those localizations survive
on a disjoint fourfold-larger world surface. It does not change the source
artifacts, prompts, parser, score, provider request, or lineage contracts.

## Counterfactual Support Semantics

The new counterfactual-complete failures are not primarily wrong final answers.
All three paths produce the expected answer and active conclusions in 63 of 64
rows. Their strict source-supported scores fall because the receiver often
misclassifies the source's epistemic status:

| Path | Support exact | Answer exact | Active conclusions exact | Full source-supported |
| --- | ---: | ---: | ---: | ---: |
| Direct source | 42 / 64 | 63 / 64 | 63 / 64 | 42 / 64 |
| Oracle literal | 47 / 64 | 63 / 64 | 63 / 64 | 46 / 64 |
| Model literal | 47 / 64 | 63 / 64 | 63 / 64 | 46 / 64 |

In particular, the receiver frequently calls an unresolved object-level Rule-Z
conflict a `contradictory` source even when the source contains one complete,
internally usable dependency system. The experiment therefore exposes a
meta-level distinction:

```text
object-level conclusion conflict != source-level dependency contradiction
```

Endpoint-only accuracy would hide this confusion. The strict score is doing
useful work, but the resulting failures should be named support-status or
epistemic-integration failures rather than undifferentiated reasoning errors.

## Exact Extraction Versus Downstream Use

Among 256 model-literal compute rows:

- all eight upstream typed values are exact in 144 rows;
- 115 of those 144 reach the full source-supported result;
- 29 fail after exact upstream extraction;
- those 29 rows span 12 artifact cases and 9 underlying world pairs; and
- 51 value-inexact rows nevertheless reach the correct endpoint.

The 29 conservative downstream failures split into two different families:

| Artifact family | Exact-upstream failures | Support-only failure | Answer or active-conclusion failure |
| --- | ---: | ---: | ---: |
| `counterfactual_complete` | 15 | 14 | 1 |
| `dependency_omitted` | 14 | 0 | 14 |

Thirteen of the 14 counterfactual support-only rows preserve the exact
`conflict` answer and both active conclusions, but label the complete source
`contradictory`. The omitted-dependency rows instead fail to abstain: their
answer and active-conclusion state are not licensed by the exact typed ledger.

The pilot's four post-extraction failures were all one omitted fact-removal
case. The scale-up turns that existence proof into a repeated local pattern,
but not a general prevalence estimate. It also shows that "extraction exact,
computation failed" is not a single mechanism; support calibration and
counterfactual state computation must remain separately visible.

## Target Cue Redistributes Fidelity

Paired target-cue transitions are computed within each case and replicate:

| Target | Pilot improved / regressed | Scale-up improved / regressed | Scale-up net |
| --- | ---: | ---: | ---: |
| Direct source compute | 4 / 0 | 10 / 3 | +7 |
| Oracle-literal compute | 3 / 1 | 15 / 3 | +12 |
| Model-literal compute | 2 / 0 | 15 / 3 | +12 |
| Active conclusions | 13 / 0 | 24 / 4 | +20 |
| Active rules | 1 / 7 | 5 / 15 | -10 |

The pilot's direction reproduces: target preannouncement favors the queried
consequence while reducing active-rule fidelity. Its per-pair magnitude is not
constant, and regressions now occur, so this is not a uniform capacity gain.

The interaction is most visible in difficult cells. For omitted fact-removal
artifacts, source-supported accuracy moves from 0.438 to 0.750 on direct prose,
0.438 to 0.500 on oracle literals, and 0.250 to 0.562 on model literals. Under
contradictory dependencies, the oracle path moves from 0.625 to 0.938 for edge
reversal and from 0.688 to 0.938 for fact removal. The target cue changes which
distinctions dominate downstream reconstruction; it does not repair every
missing or contradictory dependency.

## Working-Hypothesis Update

The scale-up supports a more differentiated interface account:

```text
Binding changes the allocation of preserved distinctions.
Literal extraction fidelity constrains, but does not determine, downstream use.
Downstream use includes both object-level recomputation and meta-level support
calibration.
```

This is compatible with a language-expression rate limit, but it does not
establish one as the dominant bottleneck of intelligence. Several observations
push against a single-stage story:

- exact typed values can still be assigned the wrong epistemic status;
- incomplete typed values can still land on the right endpoint;
- oracle normalization helps some artifact families and hurts others;
- target binding improves one distinction while degrading another; and
- no output-only path shows whether a complete latent state existed before
  expression.

The useful hypothesis is therefore relational. Realized intelligence can be
rate-limited at binding, encoding, re-entry, object-level integration, or
support calibration, and scaffolds can either elicit a distinction or supply
part of it. Rule-Z now separates several of those observable interfaces. It
still does not answer which boundary dominates outside this controlled task.

## Next Probe

The strongest next causal control is a prospectively registered,
length-matched null cue. It should distinguish semantic target binding from
generic prompt length or extra-attention effects without rewriting this run.
The support-status split should remain an analysis dimension so that an
apparent compute gain cannot be produced merely by relabeling object-level
conflict.

After that control, crossed provider boundaries can ask whether extraction and
downstream integration failures travel with the sender, ledger, or receiver.
New relation types and local-provider training traces remain later transfer
tests, not retroactive modifications of the present calibration surface.
