# Rule-Z Revision Ear Ladder Protocol

Status: prospectively specified before live provider calls.

## Trigger And Question

The frozen revision-interface calibration reconstructed the deterministic typed
oracle packet in 216/216 case-replicates under both cues, but reconstructed the
strong oracle prose in only 50/216. Historical-first prose reached 32/108 full
readouts while current-first prose reached 18/108. Because the old run assigned
only one prose order to each case, that difference was not an exact within-case
order intervention.

This receiver-only experiment asks four narrower questions:

1. Does clause order change reconstruction when the lexical content and case
   are held fixed?
2. Does the effect survive two deterministic ordinary-prose compilers?
3. Can an explicitly excluded role-reversed note pull the receiver away from
   the operative version history?
4. Does the receiver preserve the current answer while losing historical or
   current revision atoms and active conclusions?

There is no learned sender in this experiment. Every representation is compiled
deterministically from the frozen oracle case. The experiment therefore locates
receiver-side representation sensitivity, not sender expression quality.

## Frozen Case Surface

The experiment reuses the 108 opaque revision cases generated by seed 101:

```text
6 answer-changing transitions x 4 mutation families x 3 loads = 72
3 answer-preserving transitions x 4 mutation families x 3 loads = 36
total = 108 cases
```

Every transition, mutation family, and 8/16/32-rule load cell remains present.
The case payload's earlier counterbalanced prose-order field is retained for
lineage but does not choose a condition here: every case is compiled in both
orders.

## Fixed Receiver Contract

All thirteen conditions use one provider, one completion budget, and one JSON
readout schema. The receiver must return:

- the historical revision atom;
- the current revision atom;
- current active conclusions; and
- the current `yes` / `no` / `conflict` endpoint.

All prose conditions use the same provider-visible task and condition label and
the same strong historical/current binding cue frozen in the preceding run.
Compiler, order, and excluded-note state appear only through the representation
itself. Prose never contains an explicit final answer label.

The typed anchor uses the same deterministic current packet and expected
readout as the preceding calibration. It is not crossed with prose factors.

## Prose Compilers

Two deterministic compilers carry the same revision atom and complete current
Rule-Z state:

1. `explicit_version`: binds the atoms to version `v1` and version `v2`.
2. `temporal_status`: binds the atoms to superseded and operative states.

Both include the current facts, full current rules, current priority graph,
fired rules, suppressed rules, surviving active rules, and active conclusions.
They differ only in controlled wording and sentence organization.

## Clause Order

Each compiler emits two exact within-case order conditions:

- `historical_first`;
- `current_first`.

The two atom clauses are complete sentences and are swapped without changing
their words. Character, UTF-8 byte, whitespace-word, and tokenizer counts are
audited for each within-case order pair before a provider call.

## Excluded-Note Ladder

Each compiler/order pair has three note states:

1. `none`: no excluded note; this is the clean bridge condition.
2. `aligned`: an explicitly excluded audit note assigns the old atom to a
   historical slot and the new atom to a current slot.
3. `reversed`: the same explicitly excluded audit note swaps those two atoms.

The aligned and reversed notes contain exactly the same words and atom content;
only atom placement changes. They are both declared outside v1, outside v2,
and non-operative for the case. Per case and compiler/order, their character,
UTF-8 byte, whitespace-word, and `tiktoken 0.12.0 o200k_base` token counts must
match exactly. A mismatch fails before any provider call.

The primary decoy contrast is reversed minus aligned. Comparisons to `none` are
secondary because adding any note changes representation length.

## Thirteen Conditions

```text
T_typed_anchor

T_prose_{explicit_version,temporal_status}
        _{historical_first,current_first}
        _{none,aligned,reversed}
```

With two fixed replicates:

```text
108 cases x 2 replicates x 13 conditions = 2,808 calls
```

Execution order seed is 14,921. The complete provider suite must fit one shared
`max_new_calls` ceiling before any case, run, or trial row is written. A ceiling
of 2,807 must reject with zero provider calls and zero writes.

## Deterministic Scores

Every response is parsed and scored without an evaluation LLM:

- schema validity;
- historical atom exactness;
- current atom exactness;
- exact active conclusions;
- exact current answer;
- full joint exactness;
- historical/current role swap;
- return of a distinct old answer; and
- answer-only success with structural readout failure.

Raw responses, parsed responses, scores, prompts, representation hashes, and
logical/generation/assessment identities are stored in SQLite. Validation must
reconstruct each prompt, parse, score, and lineage identity from frozen inputs.

## Qualification And Primary Estimands

The receiver task is `identified` only if the typed anchor is fully exact over
the complete case-replicate surface and in both answer-changing and
answer-preserving strata. If this gate fails, prose contrasts remain available
only as `receiver_unqualified_descriptive_only` and are not promoted as prose
representation effects.

Subject to that gate, the prospectively fixed estimands are:

1. excluded role-decoy effect: reversed minus aligned;
2. clause-order effect: current-first minus historical-first;
3. compiler effect: temporal-status minus explicit-version;
4. decoy-by-order and decoy-by-compiler interactions;
5. aligned-note and reversed-note differences from the clean bridge;
6. answer exactness minus full-readout exactness for each factor cell;
7. answer-changing versus answer-preserving strata; and
8. between-replicate disagreement for each primary outcome.

All effects are paired by provider, case hash, replicate, and every factor not
named in the contrast. The aligned/reversed contrast is valid only for pairs
that pass the exact surface-match audit.

## Prospective Adaptive Branches

These branches require a new protocol and database:

1. If absolute reversed-minus-aligned full-exactness exceeds 0.05, add a
   two-stage receiver that extracts role assignments before producing the
   endpoint.
2. If absolute clause-order effect exceeds 0.05 in either compiler, add a
   sentence-index control and a third independently authored compiler.
3. If compiler-by-order interaction exceeds 0.05, separate lexical role markers
   from discourse order in a crossed micro-surface.
4. If answer exactness exceeds full exactness by more than 0.20, split atom,
   active-conclusion, and endpoint reconstruction into forced intermediate
   choices.
5. If more than 5% of comparable cases disagree between replicates for a
   primary metric, increase repetitions before provider comparison.

## Promotion Contract

Promotion requires:

- exactly 108 cases and 2,808 successful trials;
- thirteen unique conditions in every case-replicate block;
- exact aligned/reversed and clause-order surface audits;
- complete prompt, parse, score, and lineage reconstruction;
- zero missing or unexpected logical identities;
- SQLite `integrity_check: ok`;
- an exact zero-call resume with an unchanged database hash; and
- no selective retry, case replacement, or performance-dependent stop.

Transport or quota failures remain in the operator record but never become
stored successful trials. No API secret is stored.

## Interpretation Boundary

This experiment can identify prompt-local receiver sensitivity to deterministic
prose compiler, clause order, and explicitly excluded role-reversed material.
It cannot show that a latent state was absent, that a learned sender could not
express it, that the behavior persists across models or conversations, or that
language expression generally rate-limits intelligence.
